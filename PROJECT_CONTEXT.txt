--------------------------------------------------------------------------------
1. PRODUCT GOAL
--------------------------------------------------------------------------------

Automated trading pipeline driven by Telegram pump/dump signal-bot messages:

  Telegram source
    → ingest (Telethon user session)
    → parse signal
    → validate
    → size position
    → execute on Bybit USDT linear perpetual (Demo Trading or mainnet)
    → set TP/SL from actual fill price
    → notify operator via optional Telegram Bot API bot

Business mapping (encoded in parser, not in exchange layer):

  DUMP → logical BUY  → open LONG
  PUMP → logical SELL → open SHORT

Primary signal source: external Telegram bot (e.g. pump_screener_bot style),
configured via TELEGRAM_SOURCE_USERNAME or TELEGRAM_SOURCE_CHAT_ID (not hardcoded).

4. ARCHITECTURE (Clean Architecture / dependency inversion)
--------------------------------------------------------------------------------

Layers (dependency arrows point inward):

  domain/          — models, enums, ports (protocols). No Telethon, aiogram, pybit.
  application/     — use cases: parse, validate, size, orchestrate, format notices
  infrastructure/  — Telethon, aiogram, Bybit gateway, SQLite adapters
  core/            — Settings, errors, logging
  tools/           — simulate_signal CLI (uses application + infrastructure)

Hard rules (.cursor/rules):
  - Domain MUST NOT depend on infrastructure or SDKs
  - Application MUST NOT import telethon.*
  - Telegram infra MUST NOT import Bybit infra
  - Business logic MUST NOT live in transport handlers
  - Telethon events → internal DTO before leaving infra
  - Handlers thin: receive → map → dedupe → process → log
  - Pipeline: Message → Parser → Validator → Risk → Executor
    (never handler → order)
  - No orders from Telegram/operator-bot command handlers
  - No secrets in logs, tests, docs, .env.example
  - Production/live trading requires explicit kill-switch
  - Paper/demo before mainnet

Package map (important paths):

  app/main.py
    seeds RuntimeConfigService, starts OperatorBotService (optional),
    builds TradingSubsystem (if env TRADING_MODE demo|mainnet),
    starts TelegramIngestionService with LoggingMessageProcessor

  app/infrastructure/telegram/
    service.py, client.py, mapper, auth.py, proxy.py, session.py
    → TelegramMessageEvent DTO

  app/application/telegram/
    message_processor.py   — log + parse + notify + orchestrator.handle
    deduplicator.py        — in-memory event_id dedupe

  app/application/trading/
    signal_parser.py       — text → ParsedTradingSignal
    validator.py           — age / edited / exchange
    instrument_resolver.py — SYMBOL → SYMBOLUSDT
    position_sizer.py      — margin × leverage / price → qty
    orchestrator.py        — end-to-end execution
    bootstrap.py           — factory + Bybit preflight
    runtime_config_service.py
    order_link_id.py, decimal_math.py

  app/infrastructure/bybit/
    client.py (HTTP factory, recv_window=20s, max_retries=1)
    gateway.py (TradingGateway adapter)

  app/infrastructure/persistence/
    sqlite_execution_store.py
    sqlite_runtime_config.py
    sqlite_files.py (writable parent check)

  app/infrastructure/bot/
    service.py, handlers.py, notifier.py

  app/domain/trading/     — ParsedTradingSignal, TradeIntent, ports
  app/domain/telegram/    — TelegramMessageEvent, event_id
  app/domain/notifications/

Runtime pipeline (when trading enabled):

  Telegram
    → Telethon (infra)
    → mapper → TelegramMessageEvent
    → InMemoryEventDeduplicator
    → LoggingMessageProcessor
         → TradingSignalParser
         → OperatorNotifier.signal_detected (optional)
         → TradingSignalOrchestrator.handle
              → runtime config (mode / leverage / TP/SL / age …)
              → SignalValidator
              → BybitInstrumentResolver
              → existing position check (skip)
              → PositionSizer
              → ExecutionStore.reserve (idempotent)
              → BybitGateway.create_order (market)
              → wait fill / reconcile by orderLinkId
              → set trading-stop TP/SL from avg entry
              → OperatorNotifier.order_update
    → SQLite journal at EXECUTION_DB_PATH

If env TRADING_MODE=disabled at process start:
  TradingSubsystem is not built → parse + log (+ bot notify) only; no orders.

5. SIGNAL MESSAGE FORMAT (what the parser expects)
--------------------------------------------------------------------------------

Source: external Telegram text (often with emoji; emoji ignored).

Canonical shape (case-insensitive; Unicode dashes accepted):

  ByBit – 10m – XDP
  Pump: 32.44% (0.0197-0.02609)
  Signal 24h: 1

Or dump example:

  ByBit – 10m – BTC
  Dump: 5% (95000-90250)
  Signal 24h: 1

Regex contract (signal_parser.py):
  Header:  bybit – <timeframe like 10m|1h> – <SYMBOL>
  Line:    pump|dump: <pct>% (<price_from>-<price_to>)
  Optional: signal 24h: <int>

Parsed fields → ParsedTradingSignal:
  exchange          always "BYBIT"
  timeframe         e.g. "10m"
  symbol            e.g. "XDP" (no USDT; resolver adds USDT)
  signal_type       PUMP | DUMP
  action            SELL | BUY
  change_percent    Decimal (sign as in text; dump may be stored negative in simulate)
  price_from/to     Decimal — USED ONLY for logging/notice; NOT for order sizing
  signal_24h_count  optional int — logged; NOT used for risk/sizing today

Rejection reasons (incomplete pump/dump text):
  invalid_format, missing_symbol, missing_price_range, invalid_percentage, …

Non-signal ordinary chat text → silently ignored (empty parse result).

6. EXECUTION POLICY (current behavior)
--------------------------------------------------------------------------------

Modes:
  disabled — no Bybit private session at boot if env says disabled
  demo     — Bybit Demo Trading (api-demo.bybit.com). NOT api-testnet
  mainnet  — only if ALLOW_MAINNET_TRADING=true
  testnet  — rejected at config load ("use demo")

Sizing:
  target_margin   = equity * TRADE_MARGIN_PCT / 100
  target_notional ≈ target_margin * BYBIT_LEVERAGE
  qty = floor(notional / sizing_price) to qtyStep
  If qty < minOrderQty or notional < minNotional → REJECT (never bump qty up)

Sizing price: ORDER_SIZING_PRICE = lastPrice | markPrice (exchange ticker)

TP/SL (from actual avg entry after fill):
  LONG:  TP = entry * (1 + TAKE_PROFIT_PCT/100)
         SL = entry * (1 - STOP_LOSS_PCT/100)
  SHORT: opposite
  Rounded to tickSize
  Provisional TP/SL may be attached on create; set_trading_stop may return
  Bybit 34040 "not modified" → treated as success

Skips / rejects:
  trading_disabled
  mainnet_not_allowed
  edited_message (if EXECUTE_EDITED_MESSAGES=false)
  stale_signal (message date older than MAX_SIGNAL_AGE_SECONDS)
  existing_position (EXISTING_POSITION_POLICY=skip — only policy implemented)
  instrument constraints / insufficient balance / below min notional

Idempotency:
  event_id stable from chat_id + message_id + event_type
  orderLinkId = "k2-" + sha256(event_id) truncated
  SQLite reserve before create; duplicate → reconcile, never second submit
  max_retries=1 on pybit HTTP to avoid double POST on timeout
  recv_window = 20000 ms (clock skew tolerance)

7. OPERATOR BOT
--------------------------------------------------------------------------------

Optional. Same process as python -m app when TELEGRAM_BOT_TOKEN set.
Does NOT read the signal chat. Admin-only (TELEGRAM_BOT_ADMIN_IDS).

Commands:
  /start  — short HTML: commands + current setting values (Russian labels)
  /help   — full Russian how-to + per-key descriptions + /set examples
  /get_balance — Bybit UNIFIED equity/available (needs TRADING_MODE demo|mainnet)
  /config — current values + descriptions
  /set KEY VALUE — update runtime_config in SQLite

Runtime-editable keys (stored in EXECUTION_DB_PATH table runtime_config):
  TRADING_MODE, BYBIT_LEVERAGE, TRADE_MARGIN_PCT, ORDER_SIZING_PRICE,
  TAKE_PROFIT_ENABLED, TAKE_PROFIT_PCT,
  STOP_LOSS_ENABLED, STOP_LOSS_PCT,
  MAX_SIGNAL_AGE_SECONDS, EXECUTE_EDITED_MESSAGES

Seeded from .env on first start; DB wins afterward.
Changes apply to next signal without restart.
Bybit session still only built if env TRADING_MODE was demo|mainnet at boot.

NOT editable via bot (env only):
  TELEGRAM_*, PROXY_URL, BYBIT_API_KEY/SECRET, ALLOW_MAINNET_TRADING,
  BYBIT_CATEGORY, TAKE_PROFIT_TRIGGER_BY, ORDER_FILL_TIMEOUT_SEC,
  EXISTING_POSITION_POLICY, EXECUTION_DB_PATH, bot token/admin ids

8. SCRIPTS / HOW TO RUN
--------------------------------------------------------------------------------

A) Create Telegram user session (interactive phone/code/2FA):
     python -m app.telegram.auth
   Session file: TELEGRAM_SESSION_PATH + ".session"
   Default: data/telegram/user.session

B) Main runtime (ingest + optional trading + optional operator bot):
     python -m app
   Docker:
     docker compose up --build
   Volumes: ./data/telegram, ./data/trading
   Host data dirs must be writable by container UID 1000 (or APP_UID/APP_GID)

C) Check Bybit balance via API (no Telegram):
     python -m app.tools.get_balance
   Requires TRADING_MODE=demo|mainnet and BYBIT_API_KEY/SECRET.

D) Simulate signals without Telegram (Demo only):
     python -m app.tools.simulate_signal --symbol BTC --side dump
     python -m app.tools.simulate_signal --file data/trading/test_signals.json
     python -m app.tools.simulate_signal --file ... --dry-run
   Requires TRADING_MODE=demo. --dry-run prints/parses/connects for price but
   does not place orders. 1s pause between batch rows. Failures continue;
   non-zero exit if any failed. Synthetic chat_id = -1000000000001.

D) Quality gate:
     ruff check app tests
     mypy app
     pytest

11. SAFETY / SECURITY CONSTRAINTS FOR NEXT DESIGN
--------------------------------------------------------------------------------

MUST keep:
  - No order execution from Telegram or operator-bot command handlers
  - Idempotent execution (duplicate Telegram events ≠ duplicate orders)
  - Edited messages do not auto-create a second order by default
  - Stale signal check before live trading
  - Demo before mainnet; mainnet only with explicit ALLOW_MAINNET_TRADING
  - Secrets never in logs, exception messages, tests, docs, commits
  - Domain/application free of Telethon/aiogram/pybit imports
  - Correlation id on execution path

Known ops pitfalls already encountered:
  - Demo keys ≠ mainnet ≠ testnet keys (retCode 10003)
  - Clock skew → Bybit 10002; recv_window widened to 20s
  - Docker volume owned by root → SQLite "unable to open database file"
  - PROXY_URL=127.0.0.1 inside container ≠ host proxy
  - Read-only API key → connect works, orders fail
  - --dry-run on simulate places no orders (by design)
